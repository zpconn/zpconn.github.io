Current agenda

I spent a decade building FlightAware and applying mathematics to machine learning for aviation. I’m now chief architect for Connected Aviation at Collins Aerospace, and my agenda has two halves. The first is building real-world critical systems that the world depends on, in air traffic management, airspace modernization and global aviation networks. The second is AI formal verification, aimed at what I’ve come to see as a central bottleneck in safety-critical engineering: proving that a system is correct.

Air traffic management

Architecture across Collins’ air traffic systems, from STARS, in use at every major U.S. airport, to its bid for the FAA’s Common Automation Platform, which would handle more than 44,000 flights a day.

Global aviation networks

Architecture for the networks that link airlines, airports and aircraft worldwide, organized around security: open RFCs for design decisions and “paved road” patterns that make the secure way to build the easiest.

AI formal verification

Agents that produce software and hardware designs with machine-checked proofs of correctness. I test the method in public with lean1090 and proving-sqlite.

Agentic engineering

Coding agents at scale on safety-critical programs, and the practices that let teams trust the result.

Thesis

Verification lets coding swarms scale by reducing their dependence on human review. I believe verified coding swarms obey scaling laws of their own, in productivity and economic efficiency.

twin-correlations

Nov 2026 github.com/zpconn/twin-correlations

A machine-checked proof in analytic number theory, written by AI research agents under my direction. The truncated von Mangoldt function ΛR approximates the function that detects primes using only divisors up to R, and at R = N the two agree. So the correlation of ΛR(n) with ΛR(n + 2) is a dial that ends at the twin-prime conjecture. The theorem pins that correlation to its conjectured value for every R up to Nθ with θ < 9/17, past the classical limit of 1/2.

The statement, as the Lean kernel checks it

theorem lambdaR_twin_correlation_unconditional
    (θ : ℝ) (hθ : 0 < θ) (hθ' : θ < 9 / 17) :
    ∃ c > (0 : ℝ), ∃ C > (0 : ℝ), ∀ N : ℕ, ∀ R : ℝ,
      2 ≤ N → 2 ≤ R → R ≤ (N : ℝ) ^ θ →
      |∑ n ∈ Finset.Icc 1 N,
          LambdaR R n * LambdaR R (n + 2) - twinConstant * N|
        ≤ C * N * Real.exp (-c * Real.sqrt (Real.log R))

What’s checkedThe Lean kernel verifies the theorem from its definitions across about 20,000 lines, with no added axioms and no unproved steps. It cannot verify that the definitions say what the paper means, and no human expert has reviewed the paper yet.

Proved
Theorem 1.1 in Lean 4 with no hypotheses, including formal proofs of the Bloom–Maynard energy bound and the prime number theorem for μ with classical error term
Not a record
Known methods appear to reach 4/7, by an AI computation no human has checked, and an attempt here to pass 4/7 did not succeed
Status
Draft, awaiting review by an expert in analytic number theory

cuboctahedron

Jun–Jul 2026 github.com/zpconn/cuboctahedron

A Lean 4 and Mathlib project proving a new result about billiards: no nonsingular periodic billiard path inside a cuboctahedron bounces exactly once off each of its 14 faces. One case falls to a holonomy normal form for the path’s affine return map, the other to a Bellman potential argument on a finite graph that tracks orbits as they unfold.

Why it’s hardThe Platonic solids all have omnihedral orbits, so one well-chosen example settles each. The cuboctahedron has none, and proving a negative means ruling out all 6.2 billion orders in which a path could meet its 14 faces.

Where it startedIn 2010, at a Penn State REU, Nell Kroeger, Ray Navarrete and I searched the cuboctahedron for such an orbit by computer. Our one candidate admitted no periodic path, and we left the question open (slides). This project answers it.

Status
Main theorem proved in Lean modulo a generated coverage certificate
Arithmetic
Exact rational and integer arithmetic throughout, with no floating point

igp24-axplorer

Jul 2026 github.com/zpconn/igp24-axplorer

A research toolkit for SAIR’s IGP24 competition on the inverse Galois problem, which asks whether every finite group is the symmetry group of some polynomial’s roots. For each of the 25,000 transitive groups of degree 24, and each possible number of real roots, contestants searched for an integer polynomial of degree 24 with exactly that Galois group and that many real roots. Each polynomial scored more for a small discriminant and for a target few other teams reached. The toolkit extends Axiom’s open-source Axplorer with structured algebraic generators and an autonomous research loop that trains successive generations of feedback-conditioned transformer models to propose candidate polynomials.

Targets
165,836 pairs of Galois group and real-root count, only 622 with known examples beforehand
Accepted
234 polynomials across 16 Galois groups and six real-root counts
Evidence
Exact Galois labels and field discriminants before any score claim

proving-sqlite

Nov 2026 github.com/zpconn/proving-sqlite

An experiment in whether a fleet of coding agents can produce machine-checked proofs about real, heavily used C code, and whether those proofs can be trusted. The target is the code in SQLite that decodes on-disk records from the raw bytes of a database file. The goal is a proof, about the source exactly as published, that no input can make it do anything the C standard leaves undefined. A deterministic scheduler ran 56 agent sessions over 81 hours, up to four at once.

Why trust itOne agent writes each proof, an agent from a different vendor reviews it without seeing the author’s reasoning, and nothing merges until a gate re-runs the CBMC model checker. The rules are hash-locked, each proof must fail on bugs planted by hand in the code it covers, and assumptions about outside code are recorded and checked against SQLite’s real callers, which is how one of the two bugs surfaced.

Proved
18 of 22 functions free of undefined behavior under CBMC’s checks, on three platform configurations, plus varint round-trips and value decoding against the file format
Found
Two bugs in SQLite 3.53.4, each reproduced against the unmodified source, and two blind spots in the CBMC checker itself
Still open
Record comparison, the last four functions; record unpacking is proved only up to 4 fields and 256 bytes

lean1090

Oct 2026 github.com/zpconn/lean1090

Mode S and ADS-B decoding in Lean 4, optimized by an autonomous research loop of coding agents. In each generation, the agents profile the decoder, make one change, re-prove that the decoder still equals the reference specification on every byte input, and benchmark it against rs1090, the Rust decoder it replaces. Over 26 generations, throughput rose from a sixth of rs1090’s to more than double.

Why it’s safeThe specification, theorem statements and benchmark are hash-locked before the loop starts. The agents can change how the decoder works, but never what counts as correct or fast.

Proved
All 23 capstone contracts: decoder refinement, codec round-trips and CRC properties, CPR position accuracy, Comm-B inference
Throughput
2.67× rs1090 on decoding, 2.01× with CPR position tracking
Trusted base
Lean’s standard axioms only: propext, Classical.choice, Quot.sound

aerostore

Feb–Oct 2026 github.com/zpconn/aerostore

A Rust database engine for high-ingest, constantly updated data shared between processes on one host, built with coding agents. Its goal is to replace the PostgreSQL state store behind HyperFeed, the flight-tracking engine I built at FlightAware, with ten times the sustained throughput.

How it worksEvery process maps the same rows and indexes, linked by relative pointers, and can query them in place with no server or SQL round trip. The engine still keeps what makes it a database: optimistic transactions with savepoints and predicate conflict detection, skiplist secondary indexes with a query planner, and a write-ahead log with checkpoints.

Throughput
9.09× PostgreSQL’s sustained message rate in 24-worker trials, at a p99 latency of 9 ms against 42 ms
Checked
Verus proofs of core kernels, a Lean extraction chain, TLA+ models and reference-model replay against PostgreSQL
Status
Experimental; the 10× goal and whole-engine verification are still open
